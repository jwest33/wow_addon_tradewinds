# Tradewinds standout plan

Written 2026-11-24 against v0.17.0 (main at b00c047). This is a build brief
for an agent that has not seen the conversation behind it. Read all of it
before starting, then build the phases in order. Phases A, B and C ship
together as one release, 0.18.0. The CurseForge page refresh (Phase D) comes
after that release is built, and is deliberately last.

## 1. Goal

Tradewinds has a strong engine, async games against players, trading, a
tutorial and ten languages. A survey of 14 comparable CurseForge listings
(card games and flight minigames) showed where it falls short of them:

- The surfaces around the board are plain: the lobby is rows of spell icons,
  the end screen is lines of text, packs flash on reveal with no build-up.
- No achievements, no leaderboard, no sharing. The most downloaded listing
  in the sample (Darkmoon Arcade) has all three.
- The closest rival (another author's "Deckhand", same client) sells a tie
  to the game world: zones and learned spells feed the deck. Tradewinds'
  tie is travel time, levels and flight paths only.
- The listing has no screenshots or motion, and its copy was stale.

The phases below fix the first, second and fourth, in the order that means
the listing media is captured once, at the end, with everything in it. The
third (a deeper tie to the game world: flight-aware offers, a daily puzzle,
route packs, draft) was planned and then cut by the user on 2026-11-24. Do
not build any of it.

## 3. Ground rules

These come from how the project has been run so far. They are not optional.

**Client.** WoW Forever, interface 16001. It is not retail or classic, so do
not assume an API exists because you remember it. This client has no combat
log, and some functions return "secret values": follow the pattern in
`Travel.lua` (`pcall`, type check, `issecretvalue`). Nobody but the user can
run the game. Anything unverified goes through the probe in Phase 0 and gets
a fallback.

**Engine.** `Engine/` is pure Lua with no WoW calls and a seeded generator.
Keep it that way. Bump `R.RULES_VERSION` (now 4) whenever a rule or an
existing card's behaviour changes: that ends saved matches, so do it once,
in Phase C. New optional modes that leave normal
games identical do not need a bump, but need engine tests proving that.

**Saved data.** Per character, `TradewindsCharDB`. Never delete or rewrite
what a player has.
- `C.MIGRATIONS` has 7 entries on main, but a real save in the wild is at
  schema 8 (written by an abandoned branch). If you add a migration, first
  add a no-op entry 8 with a comment saying so, and make yours 9. Each
  migration gets a test.
- Prefer additive fields defaulted in `C.Init`, the way `db.specialPacks`
  was added, over a migration.
- A match table must never be stored in two saved places (SavedVariables
  would duplicate it).
- `tests/saves.lua` loads real and constructed saves, and has the previous
  version load the new save. It must keep passing.

**Text.** Every player-facing string goes through `ns.L` with English as
the key; plurals through `ns.Plural`. After changing text run
`python tests/run_tests.py locale write`, then translate the new keys in
all nine files in `Locales/` (the locale suite fails until they are).
Batch this once per phase at most (once for the whole release is fine): hand the new keys, each with its context, to
three parallel subagents, three languages each. Use the client's official
names for creatures, spells and places. Never send translated text over
the wire. Sentences about you and about the opponent are separate keys.

**Art.** Card art stays the client's icons. Everything else is generated by
`tools/gen_art.py` into `Art/` as TGA. Running it rewrites `Board.tga`,
`CardBack.tga` and `CardRim.tga` slightly differently each time: restore
those three with `git checkout` unless you meant to change them. Wind
motifs are clean and brush-like, never curly.

**Taste, from earlier feedback.** No large card preview on hover and no
creature portraits or 3D models: both were tried and removed at the user's
request. Explain rules visually and in context, not in walls of text.

**Process.**
- Tests: `python tests/run_tests.py` (engine, ui, pvp, saves, locale). All
  green before a phase is called done. Add tests with every feature;
  `tests/ui.lua` drives the real button functions.
- Economy: `tests/engine.lua` section 8 simulates the collection pace and
  fails if it moves. Any new source of packs or shards must be added to
  that model on purpose, keeping the approved pace (about three quarters of
  the pack cards in three to four weeks, everything in two to three months).
- After any card or AI change run `balance ladder`.
- Shell quirk: heredocs containing apostrophes fail here. Write scripts to
  a file and run them.
- Git: work on one branch off main, `release-0.18`. Do not commit, tag, push or
  release unless the user asks. Commit with the repo's configured noreply
  identity. The repo is public: no character or guild member names in
  committed files (`notes.txt` and `tests/saves/` are private).
- Phases A, B and C are one version, 0.18.0: one `## Version` bump in the
  .toc, one `CHANGELOG.md` section, `README.md` updated for all of it. The
  changelog section must open by saying that matches in progress end
  (rules version 5, from the traps) and that games against players and
  trades need both sides on this version. Build the zip with
  `python tools/package.py` when all three are done; do not build or hand
  over intermediate releases.
- New `.lua` files in the .toc and new files in `Art/` need a full client
  restart, not `/reload`. Say so when handing a phase to the user.
- The phases are still checkpoints. At the end of each, give the user a
  short in-game checklist (the repo is junction-installed, so they can load
  work in progress): what to
  look at, what to send back (screenshots, `/tradewinds probe` output, Lua
  errors with `/console scriptErrors 1`).

## 4. Phase 0: probe (build it first)

Add `/tradewinds probe`: prints one line per item, value or "missing",
never erroring. The user runs it once and pastes the output. Until then
build every dependent feature on its fallback.

| Question | Used by | Fallback if missing |
|---|---|---|
| Does an addon message on the `GUILD` channel arrive? (send one to self, report on receipt) | B: leaderboard | Whisper each known Tradewinds guildmate instead |
| Guild roster: `GetNumGuildMembers`, `GetGuildRosterInfo` (name, online) | B | Board shows last-seen times only |
| Can text be put in the chat edit box (`ChatFrame_OpenChat` or `ChatEdit_InsertLink`)? | B: sharing | A copyable edit box in the window |
| Scale animations on an `AnimationGroup` | A: card flip | A squeeze tween through `UI/Effects.lua`, or a crossfade |
| `IsInGuild` | B | The guild board is hidden |

Add each probed call to `tests/wowmock.lua` only in the shape the probe
confirmed.

## 5. Phase A: spectacle

What a player sees in the first minute, and what the listing will show.

**A1. Pack opening ceremony** (`UI/Packs.lua`, `UI/Effects.lua`)
- A card turns over with a flip (squeeze to edge, swap face, widen), not an
  instant swap.
- Before a rare or better turns, its back glows in the rarity colour
  (`CardGlow`). Epic, legendary and holographic cards charge for about 0.6 s
  with a rising sound first. Commons flip at once: the wait is the tell.
- Under the cards, once all are up: "2 new cards, +3 shards".
- "Reveal all" turns them in sequence, 0.15 s apart, best card last.
- Replace the ten-line "Ways to earn packs" text block with a compact
  two-column panel of icon rows; move the long wording into tooltips.
- "Open all" keeps working, and clicking through fast must never be slowed
  by more than the charge on the fancy cards.

**A2. End screen** (`showGameOver` in `UI/Game.lua`)
- Reward cards are shown as card widgets, not names in a line.
- Shards and packs count up; an earned star stamps in with `Star.tga`.
- Buttons: Rematch, Next opponent (when one just unlocked), Back to the
  circuit. Rematch against the computer starts at once.
- The same facts stay available as text for the tests.

**A3. Lobby** (`buildLobby`)
- A generated portrait frame (`Art/Portrait.tga`) around a larger opponent
  icon; the signature card's icon and name on the row, greyed until won.
- Locked rows show a lock, not 55% alpha alone.
- The daily task gets a progress bar.
- Fix the text that says finishing the tutorial "earns a card pack" (the
  welcome box and the tutorial tooltip): it is a Windfall pack.

**A4. Board skins** (`tools/gen_art.py`, `UI/Game.lua` near line 2503)
- `Board.tga` stays the tavern table. Add `BoardShip.tga` (deck planking,
  rope edge) and `BoardSky.tga` (dusk sky, cloud bands).
- Option "Board": Automatic, Tavern, Ship, Sky. Automatic picks by
  `Travel.IsRiding` / `IsFlying` when a match is opened and does not change
  mid-round.
- Lane columns, markers and card text must stay readable on all three:
  render previews with `python tools/gen_art.py out.png 2.1` and look at
  them.

**Done when:** all suites pass, `tests/ui.lua` opens packs of every rarity
mix and finishes matches through the new end screen, effect pools stay
bounded, and the user has seen all four pieces in game.

## 6. Phase B: social

**B1. Achievements**
- `Data/Achievements.lua`: about 40, in groups (circuit, collection, play,
  travel, players, oddities), each `{ id, name, text, points, group }` and
  either a `check(db)` on saved state or a lifetime counter with a goal.
- `db.life`: lifetime counters (Morale dealt, units destroyed, units and
  tactics played, packs opened, travel seconds, games against players,
  trades). Fed from the same place as `C.TaskEvents`. Start at zero for
  existing players; say so in the changelog.
- `db.ach[id] = date`. `C.CheckAchievements(db)` returns the newly earned,
  called wherever `ns.CheckMilestones` is. Ones already true for an
  existing save are granted quietly at first login with one summary line,
  not forty toasts.
- Leave room in the list for trap achievements (Phase C).
- A toast per achievement (new kind in `UI.Toast`) and a sound.
- Achievements pay points only, so the economy test is untouched.
- A sixth tab, "Records" (there is room: tabs are 78 wide from x = 130):
  achievements by group with progress bars, then the guild board (B2).

**B2. Guild board and "who has Tradewinds"**
- Messages on the existing prefix, `GUILD` channel (see the probe):
  `LB;version;stars;heroic;owned;total;points;pvpWins` broadcast at login
  after a random 5-30 s, and at most once a minute when a number changes;
  `LQ` asks everyone to answer, sent when the Records tab opens, at most
  once every 5 minutes.
- `Net.lua` only accepts `WHISPER` today; accept `GUILD` for these two
  types alone. Do not change `N.PROTO`. Check what an older version does
  with an unknown message type and confirm it ignores these.
- `db.guildBoard[name] = { ..., seen = time }`, dropped after 30 days and
  capped at 200 names. Validate every field: this is input from other
  clients.
- The board sorts by any column. Each row has Challenge and Trade buttons,
  enabled when the roster says the player is online and their version
  matches.
- Option "Share my progress with my guild", on by default; off means
  neither sending nor answering.
- `tests/pvp.lua` gets a guild channel in its pretend network: two clients
  see each other, the opt-out is honoured, garbage input is ignored.

**B3. Sharing and deck codes**
- Share buttons on a fancy pack pull, a new star, an achievement and a
  win against a player. They put a line into the chat edit box for the
  player to send; the addon never sends chat by itself.
- Deck codes: `TW1:` plus `N.EncodeDeck`'s output. Export from the deck
  panel into a copyable box. Import validates the code, loads the cards the
  player owns, lists the ones they lack with their craft cost, and never
  writes an illegal deck silently (the curve checklist shows what is
  missing).

**B4. Games against players**
- Rematch button on the end screen: a normal challenge to the same player.
- A last-round checksum, listed as not done in `PLAN.md`.

**Done when:** suites pass, including the new pvp cases; the user has seen
the Records tab in game and pasted the probe output. A second account is
needed to see the board with another player on it; the user can make a
trial account, but it is unknown whether trial accounts can send addon
messages at all. Ask them to try a challenge and a trade at the same time,
since neither has ever run between two real clients.

## 7. Phase C: traps

Build Wave 2 of `SETS_PLAN.md` as written there (traps off the board in
`P.traps`, the opponent sees the count but not the lane, `R.Redact` for the
forecast and the AI, rules version 5). Its section 10 lists decisions still
open: ask the user about those before starting. This is what ends saved
matches in 0.18.0. Give traps the same treatment as everything else in this
plan: a first-time tip, a Guide entry with a diagram, replay effects, and
achievements of their own in the Phase B list.

## 8. Phase D: the page refresh (last)

1. **`/tradewinds demo <scene>`** (ships in 0.18.0 or a 0.18.1; it is a
   developer command either way): stages a scene on one client so the user
   can capture without a second account or luck. Scenes: `board` (a busy
   round mid-planning with markers and forecast), `reveal` (the same round
   locked in, countdown about to start), `pack` (a Windfall pack with an
   epic and a holographic card face down), `tribe` (a tribe card hovered,
   kin lit), `games` (several games against invented players in the list),
   `trade` (a trade panel with cards on both sides), `records` (a
   populated guild board), `trap` (a trap about to spring).
   - It must never touch the player's save: build the scene from a copy
     and restore on `/tradewinds demo off`, on hide and on logout. A test
     checks the saved table is identical afterwards.
   - Invented player names only. Its own text is developer-facing and not
     translated; keep it out of `ns.L` so the locale suite stays clean.
2. **The user captures** following the shot list in `media/CURSEFORGE.md`:
   screenshots with Print Screen (they land in the game's `Screenshots`
   folder), and one 10-15 s recording of a reveal and combat.
3. **Prepare the media**: crop to the window, add the captions, export at
   the listing's sizes; cut the recording to a GIF of a few MB (check that
   ffmpeg is installed first). Put the results in `media/`.
4. **Update the copy**: `media/CURSEFORGE.md` was refreshed on 2026-11-24
   for 0.17.0 (new hook, "What's different", shot list). Extend it for
   everything built in A-C and extend the shot list to match. Add the
   images to `README.md` and set the GitHub social preview.
5. The user uploads to CurseForge by hand; Automatic Packaging stays off.

## 9. Decisions for the user

Defaults are what the plan assumes. Ask once at the start of the phase
named; carry on with the default if there is no answer.

| 4 | C | The open items in `SETS_PLAN.md` section 10 | Ask; no default |
